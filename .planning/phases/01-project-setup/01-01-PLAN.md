<task type="auto">
  <name>Task 1: Create directory structure and index.html shell</name>
  <files>index.html, js/ (directory)</files>
  <action>
Create the following directory structure at the project root:

```
index.html
css/
js/
  app.js
  tasks.js
  storage.js
  render.js
```

Write `index.html` with this exact structure:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>To-Do App</title>
    <link rel="stylesheet" href="css/styles.css" />
  </head>
  <body>
    <div class="container">
      <h1>To-Do List</h1>

      <div class="add-task">
        <input
          id="task-input"
          type="text"
          placeholder="Add a new task…"
          aria-label="New task text"
        />
        <button id="add-btn" type="button">Add</button>
      </div>

      <ul id="task-list" aria-label="Task list"></ul>
    </div>

    <script type="module" src="js/app.js"></script>
  </body>
</html>
```

Key requirements:
- `id="task-input"` on the text input (Phase 2 queries by this id)
- `id="add-btn"` on the button (Phase 2 attaches click listener)
- `id="task-list"` on the `<ul>` (Phase 2 renders tasks here)
- `type="module"` on the script tag (enables ES module imports in app.js)
- Link to `css/styles.css` (Phase 2 plan 02-02 will create this file)
  </action>
  <verify>
Open index.html in a browser (or run: `python3 -m http.server 8080` and visit http://localhost:8080). Confirm:
- Page renders with a heading, an input, a button, and an empty list area
- No 404 errors in the network tab (note: styles.css 404 is expected until plan 01-02; app.js must load without errors)

Also verify DOM elements exist:
```bash
grep -E 'id="task-input"' index.html && echo "input OK"
grep -E 'id="add-btn"' index.html && echo "button OK"
grep -E 'id="task-list"' index.html && echo "list OK"
grep -E 'type="module".*app\.js' index.html && echo "module script OK"
```
  </verify>
  <done>
- `index.html` exists at the project root with the four required DOM elements (task-input, add-btn, task-list, and the module script tag)
- `js/` directory exists (even if JS files are empty stubs for now)
- File is valid HTML that renders without a blank screen
  </done>
</task>

<task type="auto">
  <name>Task 2: Create js/app.js entry module stub</name>
  <files>js/app.js</files>
  <action>
Write `js/app.js` as an ES module stub that imports the three sibling modules. This file is the entry point loaded by `index.html`.

```js
// app.js — entry point
// Imports will be wired to real implementations in Phase 2.
import './tasks.js';
import './storage.js';
import './render.js';

// TODO (Phase 2): initialise event listeners and load persisted tasks
```

Requirements:
- Must use ES module `import` syntax (not CommonJS `require`)
- Must import the three sibling modules so the browser resolves them on load
- Must not throw any runtime errors when loaded (imports resolve to valid stubs)
- No logic yet — Phase 2 fills in the implementation
  </action>
  <verify>
```bash
node --input-type=module < js/app.js 2>&1 | grep -i error || echo "No syntax errors"
grep "import" js/app.js | wc -l
```
Expected: 3 import lines, no syntax errors.

Also open index.html via a local server and check the browser console — no "SyntaxError" or "Failed to resolve module" messages should appear (all three imported files exist, even as stubs).
  </verify>
  <done>
- `js/app.js` exists and contains ES module import statements for `tasks.js`, `storage.js`, and `render.js`
- No syntax errors (node lints clean)
